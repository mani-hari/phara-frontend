## 2. Where the schedule lives, and how it publishes itself

Every post's real `publishedAt` date is committed directly into this repo,
deployed on Vercel. No cron, job, or Mac-mini dependency runs the schedule.
`isPublished()` (`src/lib/util/blog-publish.ts`) checks each post's date
against today in India time; the blog listing, post pages, markdown twins,
sitemap, RSS feed and `llms.txt` all re-check this hourly via Next.js ISR
revalidation. A post simply becomes visible the day its date arrives — nothing
can interrupt that because there is nothing running to interrupt.

## 3. AI/AEO indexing — done automatically today

- `robots.txt` (`src/app/robots.txt/route.ts`) explicitly allows every current
  Anthropic crawler (`ClaudeBot`, `Claude-SearchBot`, `Claude-User`), both
  Perplexity tokens (`PerplexityBot`, `Perplexity-User`), OpenAI's three, and
  the other major AI crawlers — confirmed against Anthropic's and
  Perplexity's own current crawler docs, not secondhand sources.
- Content Signals policy (`ai-train=no, search=yes, ai-input=yes`): open to
  citation/retrieval, not model training.
- **IndexNow**: a daily Vercel Cron (`/api/indexnow`, 22:30 UTC) pings Bing,
  Yandex, Seznam and Naver with every published post's URL and its markdown
  twin, so newly drip-published posts are pushed the same day instead of
  waiting for an organic crawl. Key file hosted per spec at
  `public/c19d6c00f7142b246af7427e6b8ab828.txt`. Google does not support
  IndexNow.
- `llms.txt`, the markdown twin route per post, and an RFC 9727 API catalog
  (from earlier work) remain correctly date-gated against the new schedule.
- `layout.tsx` now reads `GOOGLE_SITE_VERIFICATION` / `BING_SITE_VERIFICATION`
  env vars into the page's verification meta tags, so the two manual steps
  below need no further code change once done.
